## 1. Decisions

| # | Topic | Decision |
|---|---|---|
| P3-1 | **Patients (sensitive)** | File number is generated (`PAT-<branch>-<year>-<n>`) or typed. Phone and notes are encrypted at rest (Laravel `encrypted` cast); `phone_hash` (HMAC of the normalised number) finds a patient by phone. Age or date of birth. A doctor sees patients they are the primary doctor of or operated on; `patients.view_all` sees everyone (in its branch scope). Opening a patient record is written to the activity log. Never deleted. |
| P3-2 | **Surgery logging** | Header: type (configurable, translatable list), date, branch, hospital, lead doctor + assistants, patient (pick or create), kit checkout (optional), laterality, notes, photos (implant stickers). Lines: scanned implants (serial units) and lot consumables (lot + quantity). *Complete* takes everything out of stock in one transaction: units → `used_in_surgery` (customer = hospital, linked to patient), lots → quantity removed; ledger type `surgery_use`. |
| P3-3 | **Where an item may come from** | A unit is usable when it is on a shelf of the surgery's branch, or inside the kit checked out for this surgery. A unit on a shelf of **another** branch or in **another** kit is allowed with a warning stored on the line (`not_in_branch`, `not_in_kit`). Expired / blocking items need *override expired* + reason. A serial can be in only one live surgery. |
| P3-4 | **Offline draft (brief §2.3)** | The phone form is Alpine + IndexedDB (`drafts` store): header + scanned codes are saved on the phone as they are typed. *Save* / *Complete* sends the draft to `POST /app/sync/surgeries` (idempotent by `client_uuid`): the server creates / updates the surgery draft, resolves each code and, if *complete* was asked and nothing blocks, completes it. If offline, the draft waits (banner "saved on this phone") and is sent when the connection is back. Anything that blocks (expired, unknown code, used serial) keeps it a draft with the reasons, to fix online. Photos are added online. |
| P3-5 | **Cancelling a surgery** | `surgeries.cancel` + reason: every line is reversed (`surgery_reversal`): units back on the branch shelf (`in_stock`), lot quantities back into their bucket. Lines keep `reversed_at`; nothing is deleted. |
| P3-6 | **Kits & instruments** | Kit types (translatable) with a template: expected instrument types and implant products (size = product) with quantities and "required". Physical kits: code + barcode (`KIT-…`), type, home and current branch, status, photo. Instruments: code + barcode (`INS-…`), type, maker serial, branch, status, holder, optional kit. Implants in a kit stay stock of the branch: units `in_kit` with `kit_id`, lots in a kit bucket (`location_type = kit`, `kit_id` in the bucket key). Kit/instrument changes go through `AssetMovementService` (lock + append-only `asset_movements` row). |
| P3-7 | **Kit flow** | **Prepare / refill**: scan instruments and implants into the kit (from the branch shelf; FEFO hint), remove items, live comparison with the template (missing / extra). **Check out** (`kits.checkout`): hospital, doctor, planned surgery date, optional patient → a checkout with a snapshot of the contents; kit, its instruments and implants become `out_at_hospital`; due back after *overdue-kit days* (setting). **Return** (`kits.return`): scan the kit, tick instruments (returned / missing / damaged), scan implants back. Each unit is reconciled: *returned* (back in the kit), *used in surgery* (a completed surgery of this checkout has it), or *unaccounted* → one issue for the Super Admin, who resolves it (`kits.resolve_unaccounted`): found → back in the kit, used → link to a surgery, lost → written off at once (the Super Admin's decision is the approval). Lots the same by quantity. |
| P3-8 | **Kits on transfers** | `transfer_assets`: an available kit (with everything in it) or a loose instrument travels on a normal transfer. Send → `in_transit`; receive → current branch changes for the kit, its instruments and its implants (ledger rows for each). |
| P3-9 | **Overdue kits** | Daily in `stock:alerts`: kits out longer than the setting → notification to `kits.checkout` holders of the branch + the Super Admin; overdue filter + dashboard count. |
| P3-10 | **Hospitals** | `customers` (Phase 2) gets tabs: kits out, surgeries, returns. Price lists (open question 6) and credit (open question 2) stay switched off. |
| P3-11 | **Billing hook** | `surgeries.fee_amount`, `fee_currency`, `billing_status` exist (open question 4); invoice / fx columns arrive with Phase 4. |
| P3-12 | **Phone** | Tasks hub gains *New surgery*, *My surgeries*, kits (prepare, check out, return). Scan resolves kit and instrument barcodes. Doctors get a "my surgeries / my kits" view. Printed surgery reports and kit checklists come with Phase 5 (PDFs). |
